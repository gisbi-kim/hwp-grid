# HWP Grid

HWP·HWPX 문서를 브라우저에서 여러 페이지 격자로 읽는 독립적인 오픈소스 뷰어.

**본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.**

한컴/한글과컴퓨터와 제휴·후원·승인 관계가 없습니다. HWP·HWPX 명칭은 지원 형식을 설명하기 위해 사용합니다.

## 기능

- 문서 서버 업로드 없이 WebAssembly로 로컬 처리
- 기본은 항상 읽기 전용. **편집 모드**에서 별도 복사본의 본문·표 텍스트와 글꼴·크기·색상 수정
- 열 개수 조절, 확대·축소, 드래그 이동, 페이지 이동, 전체 화면
- 두 문서를 나란히 열고 각각 독립적으로 스크롤·확대·격자 조절 (좁은 화면에서는 위아래 배치)
- 페이지 우측 상단 책갈피 버튼과 왼쪽 책갈피 목록에서 즉시 이동
- IndexedDB에 각 화면의 마지막 원본 문서 저장 (최대 2개), localStorage에 화면별 보기 위치와 문서별 책갈피 저장
- 여러 문서의 페이지 정보와 읽은 페이지 SVG를 로컬 디스크에 캐시 (최대 10 GB, 가장 오래 사용하지 않은 문서부터 자동 삭제)
- 하단 **캐시 관리**에서 사용량 확인 및 전체 캐시 비우기
- 다시 접속하면 마지막 문서·열 개수·배율·위치를 복원
- 저장본 삭제 가능 (컴퓨터의 원본 파일은 수정·삭제하지 않음)

## GitHub Pages 배포

1. `gisbi-kim/hwp-grid` 공개 저장소를 만들고 이 폴더의 **내용 전체**를 main에 올립니다. `.github/`도 포함해야 합니다.
2. GitHub 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
3. Actions에서 `Deploy HWP Grid to GitHub Pages`를 실행합니다. 이후 main에 push하면 자동으로 다시 배포합니다.
4. 성공 후 주소: `https://gisbi-kim.github.io/hwp-grid/`.

`vite.config.ts`의 base 및 WASM/고지 링크는 `/hwp-grid/` 하위 경로에 대응합니다. 서버 런타임, API 키, ChatGPT 로그인은 필요하지 않습니다. 소스만 배포하므로 빌드 시 의존성을 npm에서 설치합니다.

기존 `chatgpt.site`와 GitHub Pages는 다른 origin이므로 저장된 문서는 자동 이전되지 않습니다. 새 주소에서 원본을 한 번 다시 열면 됩니다.


## 사용

파일 선택 또는 드래그 앤 드롭으로 엽니다. 상단 **문서 비교**를 누르면 두 번째 화면이 열리며, 그 화면의 **문서 열기** 또는 드래그 앤 드롭으로 비교 문서를 선택합니다. 두 화면의 위치·배율·열 개수는 독립적입니다. **닫기 / 비교 종료**는 두 번째 화면을 닫고 엔진 메모리를 해제하며, 다시 비교를 켜면 저장된 문서를 복원합니다. 각 화면의 휴지통은 해당 저장 문서·보기 위치·문서 책갈피를 삭제합니다.

페이지 우측 상단 책갈피 버튼을 누르면 왼쪽 세로 목록에 쪽 번호가 추가됩니다. 목록에서 누르면 해당 페이지로 이동하고, 페이지 버튼을 다시 누르면 책갈피가 해제됩니다. 책갈피는 로컬 파일의 이름·크기·수정 시각 조합으로 구분하여 다시 열 때 복원합니다. 같은 파일을 양쪽에 열면 책갈피는 공유하며 스크롤은 독립적입니다.

휠은 스크롤, Ctrl/Command+휠은 확대, 드래그는 화면 이동입니다. 모바일 문서 영역에서는 두 손가락을 오므리거나 펼쳐 20–800%로 축소·확대하고, 한 손가락으로 이동합니다. 문서 영역에 포커스한 상태에서 좌우 방향키로 행 이동, 0으로 화면 맞춤이 가능합니다.

문서당 최대 1 GiB (1,024 MiB), HWP·HWPX를 지원합니다. 암호 문서는 입력창에서 암호를 입력해 엽니다. HWP5 EncryptVersion 4, 압축 HWP3, ODF AES-256-CBC HWPX를 지원하며, 구버전·비압축 HWP3 암호화와 DRM은 지원하지 않습니다. 암호는 저장·전송하지 않으며 마지막 문서 복원 시 다시 입력합니다. 브라우저에는 암호가 설정된 원본 파일을 그대로 저장합니다. 복잡한 표·수식·글꼴은 한컴 출력과 다를 수 있으며, 원본 편집이나 출력 정확성을 보증하지 않습니다. 브라우저 저장은 영구 백업이 아닙니다. 웹사이트 최초 로드는 인터넷이 필요하며 별도 오프라인 서비스 워커는 없습니다.

## 배포 이력

- 1.0.0: 제공된 hwp-grid-github-ready.zip을 기반으로 최초 공개. Vite를 8.3.0으로 갱신하고 타입 검사·배포 빌드·의존성 보안 검사를 수행했습니다.

- 모바일 터치: 두 손가락 사이를 중심으로 핀치 확대·축소, 한 손가락 이동 및 손가락 수 전환을 지원합니다.

- 성능 표시: 하단에 최초 사이트 로딩 시간, 최근 문서 준비 시간, 2초 간격의 메모리 정보를 표시합니다. 최초 로딩은 Navigation Timing의 loadEventEnd 기준이며 문서 준비는 파일 읽기부터 분석까지(페이지 렌더링·표시용 글꼴·저장 제외)입니다. 메모리(JS)는 지원 브라우저의 performance.memory 추정값이며 미지원 시 명시합니다. 엔진 할당량은 WebAssembly 메모리 버퍼 크기입니다. 두 값은 전체 탭 메모리가 아니며 합산하지 않습니다. MB는 1,000,000바이트입니다.

- 혼합 용지 격자: 가로·세로 및 크기가 다른 페이지도 표시 너비를 같게 맞추고 원본 비율을 유지합니다. 행 높이는 해당 행의 페이지에 맞춰 계산하여 문서 전체의 최대 용지 크기로 생기던 여백을 줄였습니다.

- 문서 열기 최적화: 모든 Noto 글꼴 조각의 선행 다운로드를 제거하고, 표시되는 글자에 필요한 조각만 브라우저가 불러오도록 변경했습니다. 로컬 Chrome의 새 브라우저 컨텍스트에서 약 146MB·244쪽 HWPX를 각 3회 비교한 중앙값은 문서 준비 1.44→0.67초, 파일 선택부터 첫 화면과 글꼴 준비까지 2.01→1.21초였습니다. 244쪽 수와 처음 표시된 4쪽의 SVG가 동일함을 확인했습니다. 문서는 테스트용 로컬 파일이며 저장소에 포함하지 않습니다. 장치·네트워크·캐시에 따라 시간은 달라집니다.

- 스크롤 최적화: 화면 안의 페이지를 우선해 한 번에 한 페이지씩 여유 시간에 렌더링합니다. 최근 SVG는 최대 16쪽·문자열 추정 24MiB까지 재사용하며 초과하면 오래된 것부터 버립니다. SVG 안전 처리 후 중복 파싱을 없애고, 변하지 않은 페이지 내용의 재렌더링을 줄였습니다. 실제 244쪽 문서의 고정 스크롤 시험에서 아래 방향 긴 작업의 초과 시간 합계(각 50ms 초과분)가 2,616→859ms로 감소했습니다. 단일 페이지가 복잡하면 처음 그릴 때 지연은 남을 수 있습니다.

- 백그라운드 문서 엔진: 문서 분석과 원본 SVG 생성은 Web Worker에서 실행하여 스크롤·핀치 입력을 막는 시간을 줄입니다. SVG 안전 처리는 화면 측에서 계속 수행합니다. 새 파일로 교체하거나 열기를 취소하면 불필요한 작업을 종료하고, 문서 삭제·실패 시 worker를 정리합니다. 엔진 할당량은 worker의 WASM 메모리를 보고하며 JS 추정치는 worker의 JS 힙을 포함하지 않습니다. 동일 244쪽 문서·로컬 Chrome·고정 스크롤 전후 각 3회 중앙값에서 아래 방향 긴 작업 초과 시간 합계는 771→365ms(53% 감소), 위 방향은 1,102→317ms였습니다. 1·33·53·64쪽 SVG가 기존과 동일하며 모바일 핀치, 문서 교체·취소, HWP·HWPX 복구를 검증했습니다. 장치와 페이지 복잡도에 따라 결과는 달라집니다.

- 하단 정보는 성능·고지·문서 상태를 한 줄로 통합했습니다. 좁은 화면에서는 가로 스크롤하며, 측정 안내는 본문 높이를 줄이지 않는 팝업으로 표시합니다.

- 상단 제목 줄의 높이와 세로 여백을 줄여 문서 표시 영역을 넓혔습니다.

- 하단 한 줄을 성능·고지·문서 상태 세 구역으로 구분하고, 세로 구분선과 우측 정렬을 적용했습니다. 하단 상태 문구는 간결한 서술형으로 통일했습니다.

- 드래그 위치 안정화: 수정하지 않은 페이지 번호 입력란에서 초점이 빠질 때 페이지 맨 위로 재이동하지 않도록 했습니다. 문서 드래그에서는 기본 텍스트 선택과 초점 이동에 의한 스크롤을 억제하며, 문서 영역의 브라우저 자동 스크롤 앵커 보정을 끕니다. 번호 수정 후 Enter·초점 이동에 의한 페이지 이동은 유지합니다.

- 사용자 문구: 삭제 확인창·첫 화면·오류 안내를 정중한 문장으로 통일했습니다. 하단 상태 표시는 기존의 간결한 서술형을 유지합니다.

- 암호 문서: 엔진의 암호 해제 기능을 연결하여 암호 입력·재시도·취소를 지원합니다. 입력 대기 시간은 문서 준비 시간에서 제외합니다. 암호 HWP·HWPX 테스트 문서로 열기, 잘못된 암호, 취소 및 새로고침 후 재입력을 검증합니다.

- 책갈피 및 문서 비교: 문서 뷰어를 독립된 두 화면으로 분리했습니다. 화면별 저장 문서와 위치를 분리하고, 문서별 책갈피·동일 문서 간 책갈피 동기화·반응형 비교 배치를 추가했습니다. 엔진 메모리는 양쪽 합계, 문서 준비 시간은 각 화면의 값입니다. 비교 전환 시 읽던 위치를 유지하며 화면을 닫으면 해당 엔진을 해제합니다.

  검증: 타입 검사·배포 빌드, 20쪽 HWP/HWPX의 책갈피 추가·해제·이동·복원, 두 화면의 독립 스크롤·배율·저장, 비교 종료 후 엔진 해제, 390px 모바일 배치·책갈피 터치, 두 암호 문서 동시 복원, 기존 20–800% 핀치 및 244쪽 문서 드래그를 확인했습니다. 실제 244쪽 문서와 별도 20쪽 문서를 함께 표시했습니다.

- 스크롤 중 페이지 이동 방지: 페이지 번호를 입력한 뒤 스크롤하면 미확정 입력을 취소합니다. 번호 칸에서 초점이 빠져도 문서는 이동하지 않으며, 입력 후 Enter로만 이동합니다. 번호 칸 위에서 휠을 돌려도 번호를 증감하지 않습니다. 실제 244쪽 문서에서 입력 후 스크롤·초점 이동 시 782px 되돌아가던 경로를 재현해 수정했습니다.

- 책갈피 미리보기: 왼쪽 목록에 해당 페이지의 축소 이미지와 쪽 번호를 표시합니다. 원본 비율을 유지하며 목록에 보이는 부분과 가까운 항목만 그려 스크롤 부하를 제한합니다. 본문과 미리보기 SVG 식별자를 분리하여 같은 페이지를 동시에 표시해도 참조가 충돌하지 않도록 했습니다.

- 책갈피 폭: 기본 폭을 PC 174px, 모바일 123px로 이전의 1.5배로 확대했습니다. 오른쪽 경계를 마우스·터치로 끌거나 경계에 초점을 맞춘 뒤 좌우 방향키로 조절합니다. 최소 82px, 최대 320px이면서 각 문서 화면 폭의 40% 이내로 제한하며, 선택한 폭은 화면별로 브라우저에 저장합니다.

## 로컬 문서 캐시

IndexedDB의 hwp-grid-render-cache에 페이지 크기와 읽은 페이지의 SVG를 저장합니다. 원본 전체를 여러 번 복제하지 않습니다. 파일 전체의 SHA-256과 엔진/캐시 버전으로 식별하여 이름·크기·수정 시간이 같은 다른 파일과 혼동하지 않습니다. 캐시 SVG에도 매번 기존의 안전 처리를 적용합니다.

재열기에서는 페이지 정보를 바로 복원하고 캐시가 있는 페이지는 WASM 분석 없이 표시합니다. 아직 읽지 않았거나 자동 삭제된 페이지가 필요할 때만 원본을 분석합니다. 파일 내용 확인에 필요한 읽기·해시 시간과 SVG 표시 시간은 남습니다. 암호 문서는 해제된 페이지 정보나 SVG를 저장하지 않으며, 기존처럼 재열기 시 암호를 입력합니다.

캐시 데이터 한도는 10,000,000,000바이트(10 GB)입니다. SVG Blob 크기와 메타데이터 여유분을 계산하고, 브라우저 저장소 추정 사용량에 포함된 마지막 원본 저장본·다른 동일 출처 데이터 및 할당량 10%의 여유 공간을 고려해 실제 예산을 줄입니다. 한도를 넘으면 마지막으로 연/읽은 시각이 가장 오래된 문서부터 페이지 Blob까지 함께 삭제합니다. 한도보다 큰 항목은 저장하지 않습니다. 실제 디스크 사용량에는 브라우저 내부 오버헤드가 있으며 브라우저의 추정값과 다를 수 있습니다. 저장 한도 오류는 오래된 항목을 정리한 뒤 한 번 재시도하고, 계속 실패하면 캐시 없이 문서 표시를 계속합니다.

캐시 비우기는 마지막 원본 저장본·책갈피를 유지합니다. 문서 휴지통은 해당 문서의 렌더 캐시도 삭제합니다. 브라우저/프로필/사이트 주소가 다르면 캐시는 공유되지 않으며 브라우저가 사이트 데이터를 지우면 캐시도 사라집니다. 캐시는 서버로 전송되지 않습니다.

검증: npm test로 내용 식별, 중복 크기 계산, LRU, 10 GB 경계(모의 용량), 낮은 할당량, 동시 20개 문서 저장, 전체/개별 삭제, 버전 무효화를 확인합니다. npm run build로 타입 검사와 배포 빌드를 수행합니다. Chrome에서 실제 엔진으로 생성한 HWP/HWPX의 재열기 SVG 일치, 캐시 적중 시 엔진 미실행, 캐시 삭제 후 지연 분석 복구, 암호 문서 제외, 새로고침 및 관리 화면을 확인했습니다. 200 MB로 패딩한 빈 HWP에서 최초 430ms / 재열기 146ms를 관측했습니다. 이는 복잡한 실제 200 MB 문서의 성능 측정이 아니며 장치·문서에 따라 다릅니다.

## 편집 모드

기본은 항상 읽기 전용 뷰어입니다. 상단 **편집 모드**에서 원본과 분리된 복사본을 별도 엔진으로 엽니다. 본문 또는 표 셀을 클릭하면 커서가 표시되며 한글 조합 입력, 붙여넣기, 방향키, 줄바꿈, Backspace/Delete, 실행 취소·다시 실행을 지원합니다. 본문에서는 여러 줄·문단에 걸쳐 마우스 드래그 또는 Shift+방향키로 글자를 선택하고 Ctrl/Command+A로 현재 문단을 선택합니다.

본고딕·본명조·Arial·원래 글꼴, 크기, 색상, 굵게·기울임·밑줄을 지원합니다. Ctrl/Command+B·I·U도 사용할 수 있습니다. 선택한 글자 또는 다음 입력에 적용되며 문서 데이터에 반영됩니다.

### 자동저장과 세션 이력

Ctrl/Command+S와 **지금 자동저장**은 로컬 복구본을 저장합니다. 편집 모드를 연 동안 10초마다 변경 여부를 확인하여 저장하며, 한글 조합 중인 입력은 조합 완료 후 반영합니다. 원본 전체 내용의 SHA-256을 키로 IndexedDB hwp-grid-edit-drafts의 latest 레코드 하나를 원자적으로 교체합니다. 파일당 보관 버전 수는 O(1), 실제 바이트 용량은 최신 편집본 크기에 비례합니다. 저장 실패 시 이전 레코드는 남으며 화면에 실패를 표시합니다. 같은 원본을 여러 탭에서 동시에 편집하여 덮어쓰지 않도록 Web Locks로 잠급니다.

다시 편집 모드에 들어가면 이전 자동저장본 복구 또는 원본부터 새로 편집을 선택합니다. 원본부터 시작하면 다음 자동저장 시 이전 복구본을 교체합니다. 자동저장본은 렌더 캐시와 별도이며, 렌더 캐시 비우기로 삭제하지 않습니다. 브라우저·프로필·사이트 주소가 다르면 공유되지 않고 사이트 데이터 삭제 시 함께 사라집니다. 강제 종료나 브라우저 중지 시 마지막 저장 이후의 변경은 남지 않을 수 있습니다.

편집 세션 안에서는 최초 상태와 변경된 상태를 1분마다 기록하며 최대 60개를 유지합니다. 변경 없는 분에는 이력을 추가하지 않습니다. 문서 바이너리를 내용 기반 청크로 분할하여 같은 청크를 공유하므로 중복 데이터를 줄입니다. 이력 복원 직전의 미기록 상태도 보관합니다. 이 이력은 worker 메모리에서만 유지되어 편집 창을 닫으면 없어지고, 최신 복구본 하나만 디스크에 남습니다. 큰 문서나 전면 수정 시 세션 메모리 사용량은 증가할 수 있습니다.

**뷰어로 돌아가기**는 항상 확인창을 표시합니다. **복사본 저장하고 돌아가기**, **자동저장하고 돌아가기**, **계속 편집**을 선택할 수 있습니다. **복사본 다운로드**는 원래 확장자(HWP/HWPX)와 _편집본_이 포함된 새 파일명을 사용합니다. 원본 파일 경로·뷰어 저장본·원본 렌더 캐시는 수정하지 않습니다. 암호 문서는 자동저장과 다운로드 모두 같은 암호로 보호하며 암호 자체를 저장하지 않습니다. 세션 이력은 복호화된 상태로 메모리에만 존재합니다.

### 그림과 표

입력 위치를 누른 뒤 **그림 삽입**으로 PNG·JPEG·GIF·WebP·BMP를 넣습니다(30 MB 이하). **글자처럼 / 어울림 / 자리 차지 / 글 앞으로 / 글 뒤로** 배치를 선택합니다. 그림을 선택한 뒤 끌어 이동하고 우측 하단 손잡이를 끌어 크기를 바꿉니다. Shift로 비율을 유지하며 가로·세로 mm 입력도 가능합니다. 글자처럼 배치된 그림은 끌어도 배치를 유지하며 놓은 본문 위치에서 내용을 나누어 삽입합니다. 표 위에 놓으면 가까운 위·아래 경계에 삽입하여 표와 겹치지 않습니다. 다른 쪽으로도 끌어 옮길 수 있습니다. 나머지 배치의 좌표 이동은 현재 쪽 안에서 지원합니다. 그림에 겹친 글자는 Alt+클릭으로 선택합니다. 선택한 그림의 Ctrl/Command+X는 클립보드 저장 성공 후 잘라내고, Ctrl/Command+C·V로 복사·붙여넣습니다. 그림 이동 후 기존 클립보드 붙여넣기는 시스템 HTML을 사용합니다.

표 셀을 누르면 표 전체 가로·세로 크기를 mm 또는 모서리 드래그로 조절합니다. 선택 셀의 2행/2열 분할, 오른쪽/아래 셀과 합치기, 행·열 추가, 현재 행에서 표 나누기, 다음 표와 합치기를 지원합니다. 적용할 수 없는 경계나 병합 구조에서는 오류를 표시하고 변경을 되돌립니다.

머리말·꼬리말 편집과 중첩 표의 구조 편집은 지원하지 않습니다. 그림 삽입은 본문 개체로 처리합니다. 복잡한 양식의 저장 결과는 엔진 변환 특성에 영향을 받을 수 있습니다.

검증: npm test에서 원본 분리, Unicode 입력·삭제, 서식, 줄바꿈·문단 합치기, 표 편집, 실행 취소·다시 실행, 그림 배치·이동·크기, 표 분할·병합 및 HWP/HWPX 재열기를 검사합니다. 자동저장 1개 교체·원자적 취소, 세션 청크 공유·변경 없는 기록 생략·60개 한도·복원을 검사합니다. npm run build로 타입 검사와 배포 빌드를 수행합니다. Chrome에서는 Ctrl+S·10초 자동저장·복구 확인창·1분 이력·종료/다운로드·원본 유지·그림 마우스 조작·모바일 배치를 확인했습니다.

### 셀 선택·삽입·클립보드

- 셀을 클릭한 뒤 **셀 배경색**을 바꿉니다. 다른 셀까지 드래그하면 직사각형 범위의 셀 내용이 모두 선택됩니다. 병합 셀을 걸치면 해당 셀 전체를 포함하도록 범위를 확장합니다. 선택한 셀들에 배경색·글자 서식을 일괄 적용하거나 복사하고, 입력/삭제로 내용을 바꿀 수 있습니다. 기존 테두리는 유지합니다.
- **표 만들기**에서 행·열 수와 전체 가로·세로(mm)를 지정합니다. 최대 50행·50열, 총 400셀로 제한합니다. 내용보다 작은 높이는 문서 엔진이 필요한 높이까지 늘릴 수 있습니다.
- **새 쪽 추가**는 문서 맨 끝에 쪽 나누기를 넣고 새 쪽의 커서로 이동합니다. 표나 그림이 있는 문단을 분할하지 않으며 개체를 붙여넣을 때 기존 쪽 나누기 문단을 유지합니다.
- **선택 내용 복사**, **붙여넣기**, Ctrl/Command+C·V를 지원합니다. 선택한 텍스트는 서식을 포함하여, 여러 셀은 작은 표로, 표/그림 전체는 개체로 복사합니다. 표 안에서 일부 글자를 선택하지 않은 상태의 복사는 표 전체를 대상으로 하며, **표 전체 복사 / 그림 전체 복사** 버튼도 제공합니다. 같은 편집 세션에서는 엔진의 원형 복사본을 사용하고 다른 문서·앱과는 HTML/텍스트 클립보드로 교환합니다. 외부 HTML의 복잡한 서식은 변환될 수 있습니다. 시스템 클립보드의 비트맵 그림도 붙여넣습니다. HTML에서 외부 이미지 주소·스크립트는 제외합니다.
- 표 바깥을 클릭했는데 엔진이 가까운 셀을 반환하는 경우, 표 앞/뒤 본문으로 커서를 옮깁니다. 본문 문단이 없으면 하나를 만듭니다. 이후 글·표·그림을 추가할 수 있습니다. 빈 공간 입력은 문서의 본문 흐름을 따르며 자유 배치 글상자를 만드는 기능은 아닙니다.

추가 검증: 지정 크기 표 생성, 여러 셀 선택·색·서식·복사·내용 교체·실행 취소, 표 밖 입력, 표/그림 원형 및 다른 문서 HTML 붙여넣기, 새 쪽, HWP/HWPX 재열기를 npm test에 포함했습니다. Chrome에서 실제 마우스 드래그와 Ctrl+C/V, 원본 유지, 자동저장·다운로드 결과를 확인했습니다.

### 새 줄 입력 시 쪽 이동 수정

입력 문자가 이미 상속한 서식은 다시 적용하지 않습니다. rhwp 0.8.6에서 글자 크기 적용 후 줄 원점이 잘못 남는 경우에는 빈 문자열 삽입으로 해당 문단의 배치만 갱신합니다. 본문 내용과 커서 오프셋은 바꾸지 않습니다. 새 쪽에서 여러 줄 입력, 입력/선택 글자 크기 변경, 한글 조합, 커서와 SVG 페이지 일치, 실행 취소·다시 실행, 긴 본문의 실제 쪽 넘김, HWP/HWPX 재열기를 회귀 테스트로 확인합니다.

표 셀 안에서 Ctrl+←/→/↑/↓를 누르면 해당 방향의 이웃 셀 첫 입력 위치로 이동합니다. 병합 셀을 건너갈 때 원래 행·열 방향을 유지하고 표 가장자리에서는 멈춥니다. 일반 방향키는 기존처럼 글자 사이를 이동합니다. 셀 이동은 문서 내용이나 편집 이력을 변경하지 않습니다. 네 방향·표 경계·병합 셀·포커스 유지·이동 후 입력을 테스트했습니다.

본문의 여러 문단 선택은 정방향·역방향 드래그, 복사, 서식 변경, 삭제·입력 교체와 실행 취소를 지원합니다. 표/그림이 포함된 문단을 가로질러 삭제할 때는 개체를 별도로 선택하도록 안내합니다. 서로 다른 구역 또는 본문과 표 내부를 가로지르는 선택은 지원하지 않습니다.

선택한 글자는 Ctrl+Shift+,로 1pt 줄이고 Ctrl+Shift+.로 1pt 키웁니다(6–96pt). 여러 문단·셀 및 서로 다른 크기의 글자를 선택해도 각 글자의 현재 크기에서 증감하며 선택 영역은 유지됩니다. 선택 영역이 없으면 아무것도 변경하지 않습니다.

### 쪽수

편집 모드의 **쪽수 · 아래 가운데** 도구에서 **쪽수 기재하기 · 처음부터 1쪽**, **시작 쪽** 입력 후 **지정한 쪽부터 1로 매기기**, **쪽수 지우기**를 사용합니다. 지정한 시작 쪽 앞에는 번호를 표시하지 않습니다. 기존 쪽 번호·새 번호 지정을 교체하며 머리말·꼬리말의 일반 내용은 유지합니다. 숫자로 직접 입력된 장식 문구는 자동 쪽 번호로 취급하지 않습니다.

쪽수는 실제 문서 컨트롤로 저장되어 자동저장·복구, 복사본 다운로드, HWP/HWPX 재열기에 반영됩니다. 실행 취소·다시 실행도 가능합니다. 긴 본문 문단이 시작 쪽 경계를 가로지르는 경우 기존 쪽 경계를 쪽 나누기로 고정합니다. 여러 쪽에 걸친 표 내부에서 번호를 시작하려면 먼저 해당 경계에서 표를 나눠야 합니다.

### 저장된 본문 쪽 경계 복원

읽기 전용 뷰어는 파일에 저장된 본문 줄 좌표가 다음 쪽의 상단으로 돌아가는 경계를 복원합니다. rhwp 0.8.6에서 그림 뒤 본문이 이전 쪽 하단으로 계속 이어지는 경우를 줄입니다. 셀·머리말 안의 줄 좌표와 다단 구역은 제외하며, 실패하면 원본으로 다시 열어 부분 적용을 남기지 않습니다. 표시용 문서에만 적용하므로 원본 파일과 편집 복사본에는 쪽 나누기를 추가하지 않습니다. 렌더 캐시 버전을 변경하여 이전 화면을 재사용하지 않습니다.

이는 한컴과 완전히 같은 렌더링을 보장하는 수정은 아닙니다. 여러 쪽에 걸친 표, 글꼴 대체, 편집 모드의 쪽 나눔에는 차이가 남아 있습니다. 로컬 검증 문서에서는 본문 하단 넘침이 47개에서 0개로 줄었지만, 표 셀의 넘침은 남았으며 전체 쪽수도 한컴 69쪽 대비 67쪽입니다. 사용자 문서와 화면 캡처는 저장소에 포함하지 않습니다.

`npm test`에 경계 검출 회귀 테스트를 포함했습니다. 실제 파일 검증은 `HWP_PAGINATION_FIXTURE` 환경변수에 로컬 파일 경로를 지정한 뒤 `npm run test:saved-pagination`으로 수행할 수 있습니다.
